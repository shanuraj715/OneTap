**Run it alone:** `node run.mjs --only t127` (add `--visible` to watch it)

## What this test does

API checks on an in-memory database. A cloud printer is created with an API key. In the database the key is stored scrambled. The create answer, the owner's list, a waiter's list (a waiter may read printers) and the answer to a rename contain neither the key, nor the stored scrambled copy, nor any database internals ($__parent, _doc, $isNew — before the fix the printer's connection was a raw Mongoose sub-document that spread the whole printer into the answer). They say cloudApiKeySet: true and a short masked tail; the other connection fields (host, port, cloudPrinterId, agentId …) are all still there for the dashboard. Renaming the printer keeps the stored key untouched.

## Steps

1. Creating a cloud printer with a key
2. Listing, as the owner and as a waiter
3. Changing the printer

## What to expect (these must happen)

- No answer about a printer contains the key, its stored copy or database internals.
- The answers still say a key is set, with a masked tail, and keep every other connection field.

## What must NOT happen

- A waiter's printer list must NOT carry the stored key.
- A rename must NOT change the stored key.
