# T43 — Checkout — the coupon box is hidden when the platform locks Coupons for the store, and comes back when it is unlocked

**Run it alone:** `node run.mjs --only t43` (add `--visible` to watch it)

## What this test does

Runs suites/checkout-coupons.mjs against the bench's Acme store in Chrome. With Coupons available, a signed-in customer's checkout has the 'Coupon' section (code box + Apply, and a wrong code is answered). The platform then LOCKS Coupons for the store (the same per-store feature lock as Stores → the store → Features in the console): the checkout page shows no 'Coupon' section, no code box and no Apply button on a desktop or a phone, the rest of checkout (order type, total, Place order) is untouched, and the server still refuses a code for that store. Unlocked again, the box comes straight back. The store's real overrides are put back at the end.

## Steps

1. Coupons ON for the store (the bench's Acme store is on Pro)
2. the platform LOCKS Coupons for this store
3. a phone, locked
4. UNLOCKED again

## What to expect (these must happen)

- A store whose plan has Coupons (or where the platform unlocked it) shows the coupon box at checkout and wrong codes get the usual message.
- A store with Coupons locked shows no coupon section at all at checkout — desktop or phone — and the rest of checkout works.
- Unlocking Coupons brings the box back.

## What must NOT happen

- A store without Coupons must NOT show a coupon code box at checkout.
- The server must NOT accept a coupon for a store without the feature.
- The browser must NOT log errors or warnings.
