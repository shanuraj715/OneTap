## What this test does

Runs suites/soft-navigation-ui.mjs in Chrome on the bench storefront. A marker is put on the window before each click; a real page load would wipe it. The header's 'My orders' and 'Menu', a footer page link, the message bar's link, the header's Order button and (on a 375 px phone) the menu drawer's 'My orders' all change the page and keep the marker — and the browser reports exactly one page load for the whole desktop walk. On the menu page 'Menu' stays an in-page jump (#menu).

## Steps

1. Desktop
2. The menu link on the menu page, and the page-load count
3. Phone menu

## What to expect (these must happen)

- Clicking any link to another page of the store changes the page and the marker survives (no reload).
- The whole walk is one page load.

## What must NOT happen

- No link to another page of the store may reload the whole app.
- No errors in the browser.
